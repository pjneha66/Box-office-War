# Box Office War — Android APK

The game is wrapped with [Capacitor](https://capacitorjs.com) as a fully offline
Android app: every game asset is bundled inside the APK, no server needed.

## One-command release (web + Android together)

From the repo root:

```bash
bash release.sh            # auto-bumps patch version (28.15 -> 28.16)
bash release.sh 28.16      # explicit version
bash release.sh 28.16 --dry-run   # everything except commit/push/release
```

The pipeline: syntax checks + full test suite → version bump (APK +
`sw.js` CACHE) → signed APK rebuild → commit + push →
GitHub release `v<version>` with the APK attached → verifies the live site.
`npm run release` is an alias; `npm run apk` only rebuilds the APK.

## Manual APK rebuild (what the script automates)

```bash
# 1. toolchain — the script auto-detects these; set them if it cannot:
export JAVA_HOME=/path/to/jdk-21       # JDK 17+ works
export ANDROID_HOME=/path/to/android-sdk

# 2. refresh the web bundle (copies game files into www/, strips the SW registration)
node build-www.js

# 3. bump the app version (optional)
#    apk/android/app/build.gradle -> versionCode / versionName

# 4. build
cd android
./gradlew assembleRelease

# output: android/app/build/outputs/apk/release/app-release.apk
#         (also copied to dist/BoxOfficeWar-<version>.apk by the release step)
```

`adb install -r app-release.apk` installs over an existing copy **only if signed
with the same key**.

## Signing — the keystore is secret, and irreplaceable

- The keystore is **not** in git. CI loads it from repository secrets
  (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
  `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`) and writes it to
  `apk/signing/boxofficewar.keystore` only for the build.
- For a local build set `ANDROID_KEYSTORE_PATH` + the password vars, or create
  `apk/android/keystore.properties` (gitignored).
- The game's saves live in the app's local storage; an update signed with a
  different key forces an uninstall, which wipes every save. Back the keystore
  up somewhere safe and durable.
- For Play Store distribution you'd upload an **AAB** (`./gradlew bundleRelease`)
  with Play App Signing instead.

## Layout

- `build-www.js` — build step: repo game files → `www/` (gitignored), strips the
  service-worker registration (the APK serves assets locally; a cache-first SW
  would only risk stale builds).
- `make-assets.mjs` — regenerates `assets/` icon + splash sources from the
  game's `icon.svg` (needs repo-root `node_modules/sharp`).
- `android/` — standard Capacitor 8 Android project (committed; safe to delete
  and re-create with `npx cap add android`).
- Icons/splash live in `android/app/src/main/res/` (generated by
  `@capacitor/assets generate --android` from `assets/`).

## Dependency security

`apk/` is the only place this project pulls third-party packages into a shipped
artifact, so it is kept at **zero known advisories**. `npm ci` + `npm audit` are
gated in the `audit` job of `.github/workflows/ci.yml`, which fails on any
moderate-or-higher finding.

Do not move `@capacitor/*` back to 8.5.x or `@capacitor/assets` to 3.x — those
ranges pull in `tar@<=7.5.20` (critical hardlink/symlink traversal), `sharp@0.32`
(high, libvips/libheif/librsvg CVEs) and `uuid@7`/`xcode@3`. The current pins
(`@capacitor/* 8.6.x`, `@capacitor/assets 4.x`) resolve to `tar@7.5.22`,
`sharp@0.35.5`, `xcode@4.0.0` and report **0 vulnerabilities**.

Note for phones/volumes where `npm install` fails with `EACCES ... syscall:
'symlink'`: some Android `bind`+FUSE mounts reject `symlink(2)`, so npm cannot
create `node_modules/.bin`. Resolve the lockfile on a normal filesystem and
commit the resulting `package.json` + `package-lock.json`; run `npm ci` only on
CI or a host with symlink support. The APK build itself never needs a local
`node_modules`.
